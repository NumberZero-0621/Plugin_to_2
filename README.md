# AviUtl -> AviUtl2 (x64) プラグイン移植ガイド

AviUtl (32bit) 向けのプラグインを AviUtl2 (64bit) に移植する際に直面する技術的課題と、その解決策をまとめたガイドです。

---

## 1. 基本的なアーキテクチャの変更

### 32bit (x86) から 64bit (x64) へ

- **ポインタサイズ**: すべてのポインタが 4バイトから 8バイトになります。`int` と `void*` のキャストを行っている箇所は `intptr_t` や `DWORD_PTR` を使用するように修正が必要です。
- **データ構造のアライメント**: 構造体のアライメントが 32bit 版と異なる場合があります。SDK の構造体定義を正確に使用してください。

### SDK の移行

- オリジナル版 SDK（`aviutl_exedit_sdk` 等）の代わりに **[AviUtl2 SDK](https://github.com/aviutl2/aviutl2_sdk_mirror)** を使用します。
- ヘッダーファイルのインクルードパスや、ライブラリのリンク設定を `x64` 構成に更新してください。

---

## 2. プラグインのエントリポイント

AviUtl2 ではプラグインの登録方式が異なります。初期化や本体へのインターフェース取得がカプセル化されています。

- **32bit 版**: `GetFilterTable`
- **AviUtl2 版**: `RegisterPlugin`, `InitializePlugin`, `UninitializePlugin` 等の個別エクスポート関数形式。

```cpp
// AviUtl2 での基本実装例
extern "C" {
    __declspec(dllexport) void RegisterPlugin(struct HOST_APP_TABLE* host) {
        // ホスト（AviUtl2本体）情報の保持
    }
    __declspec(dllexport) bool InitializePlugin(DWORD version) {
        // 初期化処理。false を返すと読み込まれない
        return true;
    }
}
```

## 3. ウィンドウおよびプロセス管理

AviUtl2 では本体のウィンドウ構造や管理方法が変更されています。

### 本体のウィンドウハンドルの取得

`get_host_app_window()` が `NULL` を返す、あるいは初期化の非常に早い段階では取得できない場合があります。その際はウィンドウクラス名による検索が有効なフォールバックとなります。

> [!TIP]
> AviUtl2 本体のメインウィンドウクラス名は **`aviutl2Manager`** です。

```cpp
HWND hwnd = edit->get_host_app_window();
if (!hwnd) {
    hwnd = ::FindWindow(_T("aviutl2Manager"), NULL);
}
```

### 外部プロセス (Out-of-Process) との連携

UI を別プロセス (`.exe`) で動かす場合、以下の情報を起動時の引数として渡すと連携がスムーズになります。

1. **親プロセスの HWND**: ウィンドウの親子関係や、メッセージ送信用。
2. **親プロセスの PID**: `EnumWindows` で本体ウィンドウを特定する際や、本体の終了検知に使用。

## 4. 文字コードとビルド設定

### コンパイルエラー C4819 (Unicode 警告)

日本語のコメントや文字列が Shift-JIS 形式で保存されていると、x64 環境のビルドで警告やエラーが出やすくなります。

- **解決策**: 文字列リテラルを `_T()` マクロで囲み、日本語を含む箇所は **Unicode エスケープ形式 (`\uXXXX`)** で記述することを推奨します。これによりソースコード自体のファイルエンコードに左右されない安定したビルドが可能になります。

---

## 5. よくあるトラブルと回避策

### createEditHandle() でのクラッシュ

AviUtl2 では、`InitializePlugin` 内で `create_edit_handle()` を呼び出し、そこからプロジェクト情報にアクセスしますが、プロジェクトが未ロードの状態や、不正なタイミングでの呼び出しはクラッシュを引き起こすことがあります。

- **対策**: `edit` ハンドルの `NULL` チェックを徹底し、可能な限り、実際の編集イベントが発生してからハンドルを生成・取得するように設計してください。

### ウィンドウの追従 (ターゲットの特定)

32bit 版の「設定ダイアログ」に相当するウィンドウを特定する場合、AviUtl2 ではウィンドウタイトルが動的に変化（`easing_normal@uf_easing` 等）することがあります。

- **検索のヒント**:
  - ウィンドウクラス名が `#32770` (ダイアログ) であること。
  - タイトルに特定のキーワード（`@` やスクリプト名）が含まれていること。
  - 子ウィンドウに `Edit` クラスなどが含まれていること。

---

## 6. まとめ

以上の知識を活用することで、多くの 32bit 版プラグインを AviUtl2 の高速な 64bit 環境に蘇らせることができます。移植に際しては、まず「本体ウィンドウを確実に捉えること」と「SDK 関数の呼び出しタイミングを適切に管理すること」が成功の鍵となります。
